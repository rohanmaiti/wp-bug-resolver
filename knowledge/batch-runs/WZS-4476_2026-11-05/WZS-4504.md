## Bug card
- **Tenant / URL:** twos.wizcommerce.com, all form pages (e.g. Contact Us `/contact-us/`, Account › Add User). Prod.
- **Expected vs actual:** Expected no zoom on field focus, page stays at 100%. Actual: iOS Safari zooms in on focus and the fields clip at the screen edges.
- **Repro:** Mobile Safari → open any form → tap an input or select.
- **Device / login:** iPhone Safari, mobile. Add User needs a logged-in buyer; Contact Us is public.
- **Attachments:** 3 frames + ScreenRecording_11-04-2026 18-27-30_1.MP4 (Add User). Related: WZS-4501.

## Root cause
iOS Safari auto-zooms when a focused field's font-size is under 16px. At 375px the fields were 14px: the Contact form (form.default c278845) gets 14px from its own typography in post-12151.css, and the v2 search modal / variant drawer inputs are also 14px, with the header search at 13px. No site-level rule raised them to 16px.

## Changes made
Site Settings (kit #6) › Custom CSS: "" (empty) → tagged block added:
```css
/* by Claude WZS-4504 2026-11-05 */
/* iOS Safari zooms on focus when a field's font-size is below 16px */
@media (max-width: 767px) {
  input:not([type="checkbox"]):not([type="radio"]):not([type="submit"]):not([type="button"]):not([type="file"]):not([type="range"]),
  select,
  textarea {
    font-size: 16px !important;
  }
}
/* end by Claude WZS-4504 */
```
Revert: clear Site Settings › Custom CSS (it was empty before), or remove the tagged block.

## Verified
Contact Us (`?nocache`) at 375px (same-origin iframe): every text/email/tel/number input, select and textarea now has a computed font-size of 16px (Contact form, search modal, variant drawer, wishlist, header search). The page is 371px wide, so no horizontal overflow. On desktop (1960px) the Contact form fields are still 14px, so desktop is unchanged. post-6.css was regenerated.

## Flags
- **Blast radius:** this is a site-wide (kit) change by design. It affects every form field on mobile across the site.
- `!important` is used on purpose, so the rule beats per-widget typography rules with high specificity (e.g. `.elementor-12151 .elementor-element-c278845 … .elementor-field` at 14px).
- I couldn't reproduce on real iOS Safari (no device). I checked the cause instead: font-size under 16px.
- I couldn't check Account › Add User (it needs a buyer login). The global selector covers it, but please confirm on an iPhone.
- The v2 code widgets (search modal, variant drawer) use 14px inputs on mobile by default, so other tenants likely have the same problem. Consider an FE-CODE follow-up: 16px mobile inputs in the shared atoms/widget CSS.
- This also fixes WZS-4501 (Contact page zoom). That ticket can be checked against the same change.
