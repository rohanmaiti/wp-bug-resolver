## Bug card
- **Tenant / URL:** twos.wizcommerce.com, any page, hamburger navigation drawer (Elementor popup "sidebar" #1661, opened by #sidebar_button / icon cfd372d). Prod.
- **Expected vs actual:** Expected the close (X) to match the design with no blue outline. Actual: a bright blue rectangular focus ring around the X when the drawer opens.
- **Repro:** Mobile Safari → open the site → tap the hamburger → look at the X at the top right of the drawer.
- **Device / login:** iOS Safari, mobile. Logged-in state doesn't matter (the drawer is the same).
- **Attachments:** Twos_Company-86642964-….png (mobile Safari, menu open). Labels: mobile, safari, twos-company, ui, from-cursor-automation.

## Root cause
Popup #1661 has Advanced › Accessible navigation (`a11y_navigation: yes`), so when it opens Elementor moves focus to `a.dialog-close-button` (verified: `document.activeElement` is that link after opening). Neither the popup nor the site styles that button's `:focus`, so the browser's default focus ring shows: `outline: rgb(0,95,204) auto 1px` in Chrome on a scripted open, and the blue ring iOS Safari draws after a tap. Chrome hides the ring on a mouse click (`:focus-visible` false), which is why it's mostly seen in Safari. The only rules on that button are core Elementor CSS and post-1661.css (colour and size).

## Fix plan
Attempt 1 (posted before applying):
1. Open https://twos.wizcommerce.com/wp-admin/post.php?post=1661&action=elementor (popup "sidebar" #1661)
2. Popup Settings → Advanced → Custom CSS
3. Change `custom_css`: "" (empty) → add this tagged block:
   ```css
   /* by Claude WZS-4486 2026-11-05 */
   /* Accessible navigation focuses the close (X) on open; hide the browser's default blue focus ring */
   #elementor-popup-modal-1661 .dialog-close-button:focus { outline: none; box-shadow: none; }
   /* end by Claude WZS-4486 */
   ```
4. Publish, then reload /?nocache=… at 375px mobile and desktop
5. Check: focus still lands on the close button, its computed outline-style is none, and the X still closes the drawer.
Revert plan: set `custom_css` back to "" (remove the tagged block) and publish.

## Changes made
Popup: sidebar #1661 › Settings › Advanced › Custom CSS (`custom_css`): "" → the tagged block above. Revert snapshot: `custom_css` = "" and `a11y_navigation` = "yes" (not changed).

## Verified
twos.wizcommerce.com/?nocache=… on desktop and at 375px mobile (same-origin iframe). After the popup opens, the active element is still `a.dialog-close-button` and it matches `:focus-visible` (the worst case), but the computed outline-style is `none` and box-shadow is `none`. Before the fix the same case gave `outline: auto rgb(0,95,204)`. The screenshot shows the X with no ring, and clicking it still closes the popup.

## Flags
- Blast radius: #1661 is a popup template used site-wide as the hamburger drawer. That's intended, since the change only touches its own close button.
- Not tested on a real iOS Safari device. Checked in Chrome with a forced `:focus-visible` (the worst case). Please check on an iPhone.
- Accessibility trade-off: keyboard users no longer see a focus indicator on the X (Accessible navigation still moves focus there). If design wants one, add a subtle `:focus-visible` style that isn't the default blue.

## Jira comment
**RCA:** The hamburger drawer popup has "Accessible navigation" on, so it puts keyboard focus on the close (X) button when it opens. Nothing styled that focus, so Safari drew its default blue focus ring around the X.

**Fix applied:** Popup: sidebar #1661 → Settings → Advanced → Custom CSS → added at the end:
~~~css
/* by Claude WZS-4486 2026-11-05 */
/* Accessible navigation focuses the close (X) on open; hide the browser's default blue focus ring */
#elementor-popup-modal-1661 .dialog-close-button:focus { outline: none; box-shadow: none; }
/* end by Claude WZS-4486 */
~~~
This brings the UI to a close (X) button with no blue outline when the menu opens, and the X still closes the menu.

**Verified:** Home page with the hamburger menu open, on mobile (375px) and desktop.
