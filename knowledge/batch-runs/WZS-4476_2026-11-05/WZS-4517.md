summary: Cart quantity modal prints the internal "-1 = no valid suggestion" sentinel from CartValidation as "Suggested Quantity: -1", because the modal's `if (validationResult.suggest)` treats -1 as truthy. This is a storefront-wp JS bug, so no Elementor change was made.

## Bug card
- **Tenant / URL:** twos.wizcommerce.com, /cart-summary/ (Two's Company). Prod.
- **Expected vs actual:** Expected the suggested qty to be 0 or a positive available amount, or hidden. Actual: the out-of-stock message shows "Suggested Quantity: -1", and DONE stays disabled with qty 3 entered.
- **Repro:** Cart containing an unavailable/incoming product (SKU 56098, Faux Wicker Round Scalloped Side Table) → open the Enter quantity modal from the line item.
- **Device / login:** Any device. Logged-in buyer.
- **Attachments:** 1 screenshot (image-f8b44aac…png, 9:35 PM). Comment from Aryan Baliyan: "PROD BUG".

## Root cause
`storefront-wp/wp-content/mu-plugins/helpers/cart-validation.js` uses `-1` as a "no valid suggestion" sentinel in two places. `handleSuggestedValue()` (line ~46) returns `suggestCount: -1` when `min > validMax`, which is always the case for out-of-stock items where max/available = 0. `getInitialEntityError()` (line ~168) hard-codes `suggest: -1` when the cart API returns a `cart_errors` entry for the line (this is where the "Product is out of stock" message comes from). The cart modal `widgets/cart-summary/js/quantity-modal.js:242` only checks `if (validationResult.suggest)`, and -1 is truthy, so it renders "Suggested Quantity: -1". The v2 `WizQuantityModal/quantity-modal.js:201` has the same check. Live evidence on twos prod: `CartValidation.handleSuggestedValue(3, 1, 0, 1)` returns `{suggestCount: -1}`. I didn't reproduce the modal itself, because the signed-in buyer's carts don't contain SKU 56098 and I didn't change a real cart.

Suggested minimal fix (not applied):
```diff
--- a/wp-content/mu-plugins/widgets/cart-summary/js/quantity-modal.js
+++ b/wp-content/mu-plugins/widgets/cart-summary/js/quantity-modal.js
@@ -242 +242 @@
-                if (validationResult.suggest) {
+                if (validationResult.suggest > 0) {
--- a/wp-content/mu-plugins/widgets/v2/WizQuantityModal/quantity-modal.js
+++ b/wp-content/mu-plugins/widgets/v2/WizQuantityModal/quantity-modal.js
@@ -201 +201 @@
-            if (result.suggest) {
+            if (result.suggest > 0) {
```
(`suggest - productTotalQuantity` can also go to 0 or negative for other ids, so `> 0` covers those too.)

## Jira comment
**RCA:** The cart's "Enter quantity" modal shows "Suggested Quantity: -1" for out-of-stock items. The storefront's cart validation (`helpers/cart-validation.js`) uses -1 internally to mean "no valid quantity to suggest" (it's returned when the item has a cart/stock error or when no quantity fits between min and available stock). The quantity modal (`widgets/cart-summary/js/quantity-modal.js`, and the same check in v2 `WizQuantityModal`) only checks whether a suggestion exists, not whether it's positive, so it shows the -1. This is a code bug, not an Elementor setup issue.

**Solution:** Show the suggestion only when it's a positive number: change `if (validationResult.suggest)` to `if (validationResult.suggest > 0)` in `widgets/cart-summary/js/quantity-modal.js` (~line 242), and `if (result.suggest)` to `if (result.suggest > 0)` in `widgets/v2/WizQuantityModal/quantity-modal.js` (~line 201). DONE stays disabled for out-of-stock items, which is expected.
