## Bug card
- **Tenant / URL:** twos.wizcommerce.com/all-products/ (All Products PLP), prod
- **Expected vs actual:** Expected: the floating Filters/Sort bar never covers price, MOQ or SKU. Actual: the bar sits over the text of the bottom cards in view (price $13.75, MOQ 4 sets, IDs)
- **Repro:** open All Products on mobile and scroll to the bottom of the grid
- **Device / state:** Android Chrome. Logged in (prices are shown), but the Chrome session here is a guest, so cards show "Login to view price"
- **Attachments:** Screenshot_20261105_091436_PLP-filters-overlap.jpg (not opened). Ticket status is Hold.

## Root cause
- Not an Elementor misconfiguration. The bar is `mobile_view_filter_widget` df3a123 (Global widget 30878) on page #12642, inside containers 71f52e2 › 8b14c28 › 9498179 › 9672c71.
- Its `.mobile-filters-container` is `position:fixed; bottom:20px; left:50%; z-index:98`. This is the widget's own inline CSS (storefront-wp `widgets/filters/mobileViewFilterWidget.php:848`). The tenant only sets width 240px and radius 0 in post-12642.css.
- Measured at 375px (same-origin iframe): the pill covers y 748–790 of the 810px viewport, which is the bottom-centre text of whichever card row is there.
- The grid `wiz_v2_product_grid` ba79129 uses infinite scroll (`wiz-plp-infinite-scroll-grid` + `infinite-scroll-sentinel`, virtualised rows), so new rows keep loading below. At the true end of the page there's ~453px of content after the grid, so the last cards can be scrolled above the pill.
- So the overlap is a floating overlay covering content while scrolling, which is how the widget is designed. Grid bottom padding (the ticket's suggestion) wouldn't change what the user sees mid-scroll.
