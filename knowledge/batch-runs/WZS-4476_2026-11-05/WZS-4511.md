- **Expected vs actual:** one loading indicator, with readable and aligned button text. Actual: a centred "Resubmitting Quote..." pill AND a spinner inside RESUBMIT QUOTE, with the button label overlapping or distorted (~28s in the recording).

## Root cause
Both loaders are coded in `storefront-wp/wp-content/mu-plugins/widgets/v2/WizQuoteResubmit/` (master):
- `resubmit.js` `setSubmitting(true)` adds `.loading` to `.wqr__btn--submit`. `style.css:595-619` then adds `padding-right:40px` and an absolutely positioned `::after` spinner (right:14px). The icon stays visible at 0.35 opacity and `.wqr__btn-text` keeps its full width. On a narrow mobile footer the extra 40px padding squeezes the label, so it wraps or overlaps the spinner.
- On success, `finishResubmitSuccess()` (`resubmit.js:~808-816`) calls `close()` and then `WizPreparingOverlay.navigate(url, 'Resubmitting Quote...')` (overlay markup from `WizQuoteResubmitWidget.php:579`). The drawer is still animating closed with the button spinner running while the centred pill appears, so two loaders show at once.
This isn't an Elementor setting. The widget's style controls (PHP lines 406-417) only set colour, background, border and radius, with no loading-state control.

## Fix plan
- (code bug, not applied)

Suggested FE fix (for the dev team):
1. In `finishResubmitSuccess`, call `setSubmitting(false)` (or skip the button spinner) before `WizPreparingOverlay.navigate`, so only the overlay shows.
2. In `style.css` `.wqr__btn--submit.loading`: hide the icon (`display:none`) instead of fading it. Either drop the `padding-right:40px` and replace the text with the spinner (`.loading .wqr__btn-text{visibility:hidden}` + a centred `::after`), or add `white-space:nowrap` to the label so it can't wrap under the spinner on mobile.

## Jira comment
**RCA:** On mobile resubmit, the "Resubmit quote to your rep" drawer (WizQuoteResubmit widget) shows two loaders by design. Tapping RESUBMIT QUOTE puts the button in a `.loading` state: an inline spinner plus 40px of extra right padding (`widgets/v2/WizQuoteResubmit/style.css` `.wqr__btn--submit.loading`). On success, `resubmit.js` `finishResubmitSuccess()` also opens the full-page "Resubmitting Quote..." overlay while the drawer is still closing. On a narrow screen the extra padding squeezes the button label, so it wraps or overlaps the spinner. This is a storefront code issue, not an Elementor/implementation setting.

**Solution (FE code):** In `resubmit.js`, clear the button loading state (or skip it) before calling `WizPreparingOverlay.navigate`, so only one loader shows. In `style.css`, change `.wqr__btn--submit.loading` so the label can't reflow: hide the icon and label text, centre the spinner, and remove the extra `padding-right`. Verify on a test quote at 375px: tap RESUBMIT QUOTE and check that only one loader appears and the button text doesn't overlap.
