## Bug card
- **Tenant / URL:** twos.wizcommerce.com/cart-summary/, cart workspace header (cart-summary header widget, `.add-products-btn`). Prod.
- **Expected vs actual:** Expected: an empty cart (0 products) shows only the empty-state message and the Browse Products CTA, with no ADD PRODUCTS. Actual: ADD PRODUCTS still shows top right, next to the kebab menu, on an empty Draft Cart.
- **Repro:** Sign in → Cart Summary → select or create an empty cart (e.g. Draft Cart, 0 products) → look at the header's top-right corner. Repeat on mobile / Android Chrome.
- **Device / login:** Desktop and mobile (Android Chrome). Needs a logged-in buyer.
- **Attachments:** empty-cart-add-products-visible.png (desktop, Draft Cart empty, ADD PRODUCTS highlighted; not viewed). Labels: cart, cta, empty-state, desktop, mobile.

## Root cause
The empty-cart update in `storefront-wp/wp-content/mu-plugins/widgets/cart-summary/CartSummaryHeaderJs.js` (master, ~L2806–2825) hides the "0 products" count (`.cart-products-count--empty`, display:none). It also hides the Save Cart wrapper (`[data-save-cart-btn-wrapper="1"]`) when `product_count === 0`. There is no matching toggle for `.add-products-btn` (rendered by `render_add_products_button()`, `cart-summary-header-functions.php:907`). The only JS that touches that button is the disable/enable logic used while switching carts (L344/L381). No CSS hides it in the empty state either: `CartSummaryHeaderCss.css` only has empty-state rules for `#cart-empty-widget` and the checkout container. The behaviour is in the shared widget, so it affects every tenant. It is not an Elementor setup problem.
Live repro was blocked: the Chrome buyer session on twos is signed out (/cart-summary/ → /user-login/?redirect_to=/cart-summary/). The ticket's screenshot and the code agree.

## Jira comment
**RCA:** On Cart Summary, the cart header widget hides the product count and the Save Cart button when the cart has 0 products, but it has no matching rule for the "Add products" button. So the button stays visible on empty carts, on desktop and mobile. This is in the shared cart-summary widget code (CartSummaryHeaderJs.js, empty-cart toggle), not in the tenant's Elementor setup.

**Solution:** FE code change in the cart-summary header widget: when product_count is 0, hide `.add-products-btn` the same way Save Cart is hidden (and show it again when products are added). Verify on twos.wizcommerce.com/cart-summary/ with an empty Draft Cart on desktop and Android Chrome: only the empty-state message and Browse Products should show.
