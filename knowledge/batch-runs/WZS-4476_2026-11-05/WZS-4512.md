## Root cause
The likely cause is the backend resubmit/email flow. The storefront drawer (`widgets/v2/WizQuoteResubmit/resubmit.js`) commits any typed-but-not-added Cc on submit (`flushPendingCcInput()`, ~L159), collects the Cc chips (`getCcEmails()`, L55) and sends them as `cc_emails` in `POST /wizshop/v1/document/quote/{document_id}/resubmit` (`buildQuoteResubmitPayload`, L769; `collectPayload`, L985). The request succeeded (the UI moved on to the Submitted page), so either the backend ignores or drops `cc_emails` when it builds the notification, or the email failed to send or deliver after the API returned. This is not an Elementor/implementation issue, because no widget setting controls who gets the email.
