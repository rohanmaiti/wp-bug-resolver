summary: WIZ v2 Sales Rep Assigned Trigger always prints the Logged-Out Text ("Find your territory manager") in PHP and JS only swaps in the Logged-In Text ("Contact…") after load, and again on every wiz:state:changed. An empty-{} userDetails during hydration flips it back to "Find". Needs a code change in the shared widget. Nothing changed.

## Bug card
- **Tenant / URL:** twos.wizcommerce.com, any page (e.g. /privacy-policy/), header top-left territory manager link; prod
- **Expected:** a logged-in buyer with an assigned TM sees one stable label, "Contact your territory manager"
- **Actual:** during load or navigation the label switches between "Find your territory manager" and "Contact your territory manager" before it settles
- **Repro:** desktop Chrome, logged in, refresh or navigate, then watch the header
- **Attachments:** header-tm-flicker.mov + 4 frames. Comment (Aryan Baliyan): "This is code change"

## Root cause
`storefront-wp` master, `wp-content/mu-plugins/widgets/v2/WizSalesRepAssignedTrigger/WizSalesRepAssignedTriggerWidget.php:208-210` always server-renders `srat_logged_out_text` ("Find…") as the label, because PHP doesn't know the browser login state. `sales-rep-assigned-trigger.js:71-75` then picks the logged-in text after the JS runs, which gives the first Find → Contact swap. The script also re-runs `syncAll()` on every `wiz:state:changed` / `storage` event (`:161-171`). `isStorefrontUserLoggedIn()` (`:26-40`) returns **false straight away** when WizState holds an empty `{}` userDetails and never checks the localStorage fallback. So while state rehydrates the label goes back to "Find", then to "Contact" again, which is the alternation in the recording. No Elementor control can stop this, because the label text comes from code.

## Fix plan
- (not applied: code bug. Suggested direction for the FE team.)
  1. Hide `.wiz-srat__label` until the first JS sync, e.g. render with `visibility:hidden` / a `wiz-srat--pending` class and remove it in `syncAll()`, or decide login state server-side from the auth cookie and print the right text in PHP.
  2. In `isStorefrontUserLoggedIn()`, don't treat an empty `{}` WizState userDetails as logged out when localStorage `UserDetails` / `persist:root` still has a token, so the label can't drop back to "Find" during rehydration.

## Jira comment
**RCA:** The header's territory manager link is the WIZ v2 Sales Rep Assigned Trigger widget. Its PHP always prints the logged-out text ("Find your territory manager"). The JS replaces it with the logged-in text ("Contact your territory manager") only after the page loads, and runs again on every state change. While user state rehydrates, the WizState userDetails can be briefly empty, which the widget reads as logged out, so the label goes back to "Find" and then to "Contact" again.

**Solution (code, storefront-wp):** In `widgets/v2/WizSalesRepAssignedTrigger/`, keep the label hidden until the first JS sync (or pick the text server-side from the auth cookie), and in `isStorefrontUserLoggedIn()` fall back to the localStorage token instead of returning logged-out for an empty userDetails object. No Elementor change can fix this.
