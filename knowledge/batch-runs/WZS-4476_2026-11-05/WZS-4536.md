## Bug card
- **Tenant / URL:** twos.wizcommerce.com/all-products/?search=<image asset URL>&type=ai-image (Two's Company). Prod. PLP.
- **Expected vs actual:** Expected an X or "Clear search" control on the visual-search chip that goes back to the default All products grid. Actual: "Search results for [thumbnail + Image.png]" has no dismiss control, and the header search overlay X doesn't clear it.
- **Repro:** Run an AI/visual search by uploading an image → land on /all-products/?search=<image URL> → try to clear it and get back to the full listing.
- **Device / login:** Desktop (label `desktop`). Login state not stated.
- **Attachments:** 4 frames + recording ai-search-no-revert.mov. Comments (Aryan Baliyan): "Need to be code change" and "PR is already present for this, its just haven't merged yet".

## Root cause
`storefront-wp/wp-content/mu-plugins/widgets/SearchModern/SearchedValueWidget.php` (master), `render()` around lines 86-120: the `.searched-value-container` prints only the "Search results for" title plus the image thumbnail or the query text. There is no clear/remove link (for example to the same URL without `search`/`type`), and `register_controls()` has no option to add one. So no Elementor setting can fix it, and a code change is required. This matches the team comment that a fix PR is pending.

## Jira comment
**RCA:** The "Search results for" chip on the PLP comes from the WIZ: Searched Value widget (`widgets/SearchModern/SearchedValueWidget.php`). Its markup shows only the title and the searched image/text. It has no clear/remove control, and no Elementor setting adds one, so visual (`type=ai-image`) and text searches can't be dismissed from the results header.
**Solution:** Code change in the widget: add an X / "Clear search" control to `.searched-value-container` that links to the current page URL without the `search` and `type` params (restoring the default listing). A PR for this already exists and needs to be reviewed and merged. Nothing can be fixed from Elementor.
