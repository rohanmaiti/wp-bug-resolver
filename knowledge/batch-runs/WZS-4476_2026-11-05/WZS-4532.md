summary: The flipbooks widget on /catalogs/ is in inline mode, so the catalog PDP (and its Enter quantity modal) runs in a nested iframe. The quantity modal only locks the body of its own frame, never the outer /catalogs/ page, so the outer page still scrolls to the footer. Needs a code change. Nothing was changed.

## Bug card
- **Tenant / URL:** twos.wizcommerce.com/catalogs/ › flipbooks_widget f2b2930 (open_mode = inline) › open a catalog (Publitas iframe) › click a product (e.g. Glass Heart Decor / Paperweight Unit, SKU 56072) → PDP. Prod.
- **Expected vs actual:** Expected the background not to scroll while the Enter quantity modal is open. Actually the page scrolls down to the footer behind the dimmed overlay, and the modal stays open.
- **Repro:** Open the catalog PDP › tap the quantity field to open Enter quantity › scroll with the trackpad or the scrollbar.
- **Device / login:** Desktop (labels). Logged-in buyer (needed for quantity/cart).
- **Attachments:** frame_000–050.jpg and quantity-modal-background-scroll.mov (not viewed).

## Root cause
On /catalogs/, flipbooks_widget f2b2930 has `open_mode: "inline"` (checked live in its data-config). In inline mode, the viewer is a 693px iframe placed inside a page that can scroll (document height 1341 vs viewport 992, with the footer below), and the widget never locks the page's scroll. The dialog mode does lock it: `$('body').css('overflow','hidden')` in `widgets/flipbooks/partials/render-scripts.php:350`, but the inline branch at :330-342 has no such line. The PDP opens inside the Publitas iframe as a nested iframe (`/product-details/…?hide=true`, see WZS-4531). Its quantity modal locks only `document.body` of that nested frame: v2 `widgets/v2/WizQuantityModal/quantity-modal.js:44` (`wiz-qty-modal-body-locked`) and v1 `widgets/cart-summary/js/quantity-modal.js:72` (`body.style.overflow='hidden'`). So scrolling by wheel chaining or by the outer scrollbar still moves the outer /catalogs/ page. The overlay only covers the iframe.

Suggested code fix (for the FE team, not applied): when the PDP runs embedded (`body.pdp-hide-chrome`), have the quantity modal open/close also lock/unlock `window.top.document.body`. The top frame is same-origin (twos.wizcommerce.com), so wrap it in try/catch. Another option is a postMessage that the flipbooks widget handles in inline mode. Implementation workaround (product decision, not applied): set Flipbooks › Open mode inline → Dialog. Dialog mode is full-screen and locks the body.

## Jira comment
**RCA:** On /catalogs/ the Flipbooks widget opens catalogs **inline**, so the product page (and its Enter quantity popup) runs inside an embedded frame. The popup locks scrolling only inside that frame, not on the outer Catalogs page, so the outer page can still scroll to the footer behind the overlay.

**Solution:** Code fix needed (storefront): when the product page runs embedded in the catalog viewer, the quantity popup should also lock and unlock the outer page's scroll. In inline mode, the Flipbooks widget should do the same. Interim option (product decision): switch the Catalogs page › Flipbooks widget › Open mode from Inline to Dialog. Dialog opens full-screen and already locks the page scroll.
